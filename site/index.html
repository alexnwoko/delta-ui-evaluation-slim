DELTA UI component library evaluation

Six candidates, each implementing the same DELTA screen. Every score below is backed by a runnable demo, a measured build, or a line of DELTA source — nothing is scored from documentation alone.

The showcase is presented in English. Every demo also carries a language switcher covering the six official UN languages plus Portuguese, so the design is demonstrably built for them — but English is the default state, not a translated one.

Baseline DELTA-Learning @ d0ebd47 · demos built with Vite 7.3.6 / React 19.2.4 · 11 August 2026

Provisional evidence, not an adoption decision

Scores are the analyst's reading of measured evidence against weights proposed here and not ratified by UNDRR. They do not establish accessibility conformance — no candidate in this field publishes a VPAT — and they do not substitute for human accessibility review or for a UNDRR architecture decision. Re-weight the criteria on the Criteria tab and the ranking recomputes.

Ranking

Weighted against the four criteria UNDRR prioritised: accessibility, styling interoperability, data functionality, and continuity across DELTA, Mangrove and other UNDRR properties.

Read with care. "Continuity" is modelled, not measured — it rests on which stack UNDP's design system and UNDRR's own Mangrove actually use, not on a running multi-property deployment. Accessibility scores rank published evidence and remediability, not conformance.

Hard gates

Failing any of these removes a candidate regardless of score.

What the demos actually show

Language and direction

DELTA ships seven languages. The question is not whether DELTA's strings translate — they do, in every demo — but whether the library's own strings do: pagination summaries, "select all rows", empty states, column filter menus, date pickers. A library that ships no locale packs hands that work, and its permanent maintenance, to DELTA.

Runnable demos

Each candidate ships two pages built from one shared dataset and one shared host shell, so what differs between them is the library and nothing else. Inside every demo: DELTA screen is the disaster-records list — search, hazard filter, nine columns, status tags, row actions, sorting, selection, pagination, a confirm dialog and a toast. Inventory is the kitchen sink of everything DELTA's 33 PrimeReact modules cover. The ع · RTL switch in each demo is the point of the exercise.

Try this in each demo

  • Press ع · RTL. Does the layout mirror? Do the library's own strings — pagination, "select all", empty state, date picker — become Arabic, or stay English? Do the numerals become Arabic-Indic?
  • Put the mouse down and use the keyboard. Tab to the table, then arrow keys, Home/End, type-ahead, Shift+click for a range. React Aria and Carbon behave like a grid; the others behave like a list of links.
  • Open the delete dialog and press Escape. Where does focus land afterwards? It should return to the button you opened it from.
  • Sort a column, then read the header. Is aria-sort set, or is the arrow purely visual?
  • Compare the Inventory pages side by side. This is the real breadth question: how much of DELTA's existing component surface comes for free, and how much you build.

Findings that only appeared when the code was built

None of these are in any candidate's documentation. Each was produced by compiling the demo on this page.

Method

  • One screen, six implementations. Identical dataset (120 records), identical host shell, identical feature list. The host chrome is plain CSS so it cannot flatter or handicap any candidate.
  • Licences read from published tarballs, not from the npm license field and not from vendor marketing. primereact@11.1.0's LICENSE.md was downloaded and read.
  • Payload measured, never cited. Each demo is a real vite build; figures are gzip of the emitted assets.
  • DELTA coupling counted with ripgrep against the checkout — 263 imports, 82 of 270 .tsx, 33 modules, 0 tests selecting on PrimeReact DOM.

Two naming points, because they cause confusion

  • "MUI" and "Material UI" are the same product. The candidate here is @mui/material 9.3.1 — Material UI, by MUI (Material-UI SAS). It is evaluated on its community MIT tier only; MUI X Pro and Premium are excluded by DELTA's licence policy, not by preference. Note also that Material UI v9 is not built on Base UI — verified from its dependency tree — so MUI's accessible-primitive work is going into a different product than the one you would adopt.
  • Google's own @material/web is a different thing, and is not a candidate. It implements Material Design 3 as web components rather than React, and its README states plainly: "MWC is in maintenance mode pending new maintainers." The last stable release is 2.5.0; everything since is nightly builds. A UN platform with a ten-year horizon should not adopt an unmaintained component layer.

Limits — read these before quoting a number

  • No candidate here publishes a VPAT or ACR. Accessibility scores rank published evidence and remediability. They are not conformance claims and do not replace an audit with real assistive technology.
  • Continuity is modelled. It is inferred from what UNDP's design system and UNDRR's Mangrove are built on — not from a running multi-property deployment.
  • The demos are client-rendered. DELTA runs React Router v7 with SSR on. The SSR costs described for Ant Design and MUI are read from their documentation and issue trackers; they were not reproduced here.
  • Baseline is the learning fork at d0ebd47 (7 May 2026). Re-baseline against unisdr/DELTA before committing to estimates.
  • MUI is evaluated on its community tier only. Anything requiring MUI X Pro or Premium was excluded by DELTA's licence policy, not merely by preference.
  • Weights are proposed, not ratified. They are the analyst's, and they change the ranking. That is why they are editable.
  • Translations in the demos are illustrative. They exist to show which strings each library owns versus which DELTA owns. They have not been reviewed by UNDRR translators and should not be reused as copy.
